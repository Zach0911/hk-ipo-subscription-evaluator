# 数据来源

## 检索原则

港股 IPO 申购数据变化快，必须使用最新可查信息，并标注来源与日期。

优先使用官方和一手来源：

1. HKEXnews / 披露易：招股书、聆讯后资料集、配发结果公告。
2. HKEX / FINI 相关页面：上市流程、发行机制、时间安排。
3. 公司招股章程：业务、财务、风险、募资用途、基石投资者。
4. 券商 IPO 页面：申购期阶段性孖展/认购热度、入场费、截止时间。
5. 金融数据 skill 或数据终端：港股行情、估值、同业数据。
6. 可靠财经媒体：补充发行反馈和行业背景。

## 当前 IPO 需要收集

| 信息 | 用途 |
|---|---|
| 公司名/代码 | 确认标的 |
| 申购开始/截止日期 | 判断是否仍处于申购期 |
| 预期定价日/上市日 | 判断当前阶段 |
| 发行价区间 | 估值判断 |
| 发行市值/募资规模 | 与历史样本比较 |
| 每手股数/入场费 | 资金效率判断 |
| 公开发售比例/国际配售比例 | 筹码结构判断 |
| 回拨机制 | 散户分配与热度风险 |
| 基石投资者 | 机构认可度判断 |
| 保荐人/承销商 | 历史定价质量判断 |
| 募资用途 | 成长性与资金需求判断 |
| 财务摘要 | 收入、利润、毛利率、现金流 |
| 风险因素 | 一票否决或降档依据 |

## 阶段性孖展/认购热度

阶段性孖展可作为辅助指标，但不能单独决定“参与”。

使用时必须区分：

- 申购期阶段性孖展/认购热度：可用于当前申购判断。
- 截止后最终认购倍数：只能用于复核或历史样本库。

判断方式：

- 热度低：可能代表市场兴趣不足，需结合基本面判断。
- 热度适中：有助于说明市场接受度，但仍需看估值。
- 热度过高：可能导致中签率低、融资成本高、收益风险比下降。

## 不应误用的数据

以下数据不是申购期核心输入：

- 暗盘表现
- 中签率
- 配发结果
- 最终认购倍数
- 首日涨跌
- 上市后 5 日/20 日走势

如果用户提供这些数据，先判断是否已经过申购期。若已过申购期，切换到复盘或交易评估，不再输出申购建议。

## 本地能力

可优先考虑这些已安装能力：

- `finance-all-in-one`：已安装到 Codex skill 目录时，可通过本 skill 的 `scripts/finance_all_in_one_adapter.py` 获取港股 K 线、行情、估值。
- 本 skill 自带脚本：`scripts/match_peer_ipos.py` 可从 `data/hk_ipo_history.csv` 匹配近 1 年同类 IPO 并计算历史表现。
- 本 skill 自带脚本：`scripts/fetch_hkex_ipo_list.py` 可抓取 HKEX 当前 Main Board/GEM 新上市信息表。
- 本 skill 自带脚本：`scripts/enrich_ipo_returns.py` 可用 `finance-all-in-one` 港股 K 线补齐历史样本收益。
- `futuapi`：可用 `scripts/quote/get_ipo_list.py HK` 获取 IPO 列表。
- `ftshare-all-in-one`：可查港股行情、估值、公司信息。
- `wind-mcp-skill`：可查港股/美股行情、基本面、事件、公告新闻。

如果调用外部或本地数据失败，不要编造数据；改为列入数据缺口并降低置信度。

## 历史样本库维护

维护方式：

1. 先运行 `python scripts/fetch_hkex_ipo_list.py --board all` 抓取 HKEX 当前新上市信息。
2. 从 HKEXnews、券商页面、金融数据终端或人工整理表补充发行价、上市日期、行业、估值等字段。
3. 按 `data/hk_ipo_history.csv` 表头整理字段。
4. 运行 `python scripts/update_hk_ipo_history.py --input new_rows.csv` 合并。
5. 运行 `python scripts/enrich_ipo_returns.py` 用 `finance-all-in-one` 补齐首日/5 日/20 日收益。
6. 评估时运行 `python scripts/match_peer_ipos.py ...` 生成样本统计。

HKEX 当前新上市信息表可自动抓取；发行价、行业、估值、保荐人、基石等深度字段仍需从招股书、公告、券商页面或金融数据终端补齐。若网页结构变化导致抓取失败，必须标注数据缺口并回退到人工检索。
